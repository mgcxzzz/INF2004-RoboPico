# Buddy 1 heartbeat timing investigation 27 October 2026

The first full 300-second connectivity run received 300 heartbeats with no
sequence gaps. The delivery estimate passed. The heartbeat receive-gap
requirement failed: five gaps exceeded 2 seconds, dashboard maximum
2.647 seconds. An independent native MQTT subscriber measured 2.645481
seconds over the same window. The dashboard verdict is supported by that
independent trace, not dismissed as a rendering artefact.

The delayed messages arrive in bursts. Their decoded Pico uptime values
continue in one-second steps. This suggests a transport delay rather than
lost messages, but the uptime field has only one-second resolution and is
not a precise transmit timestamp.

An unchanged-firmware 80-second loopback comparison kept all additional
test traffic on the Mac. The Pico heartbeat path had a 3.276638-second
maximum gap, while the local 200 ms publish/subscribe stream had a
0.203282-second maximum gap. There were no diagnostic process errors.

A separate unchanged-firmware 80-second gateway-ping comparison observed
a 2.440805-second heartbeat gap while router ping replies continued.
The largest router RTT was 233.570 ms; the largest observed interval
between router reply lines was 0.417 seconds. One ping timeout indication
was followed by a reply. The router trace does not show the same multi-
second outage, but this experiment cannot identify the exact station,
access-point, driver or transport cause.

The current evidence points towards the Pico-to-AP-to-Mac transport path.
It does not prove a Pico defect or a power-saving defect. A useful next
controlled experiment is to disable Pico WiFi power saving through the
WiFi service context and repeat the same test. No firmware or router
settings were changed during these diagnostic comparisons. The original
2-second requirement and failed result remain unchanged.

## PM off repeat outcome

The controlled PM-off build completed a new full 300-second test with 300/300 heartbeats and zero sequence gaps. Dashboard max gap was 1.124 s with zero gaps over 2 s; native subscriber max was 1.124805 s. Both criteria passed for the Buddy 1-only run. Boot API/readback verified power saving disabled. This supports retaining the PM-off local setting for this hardware/network; it does not prove performance on every network or under integrated subsystem load. The initial failed result and its evidence remain intact.
