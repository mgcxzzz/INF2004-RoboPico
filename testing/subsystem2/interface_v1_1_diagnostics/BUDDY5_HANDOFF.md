# Buddy5 with V1.1 DIAG1

This folder preserves the InterfaceV1.1 nav API, standalone circuit harness and startup fix. It adds observational diagnostics, not a new driving policy. Use [README.md](README.md) for the UF2/start/save/dump procedure. `p` is normal motion, `d` detailed drive state, `z` coordinator requests/results. Dumps occur only after stopping. Diagnostic bank0x1ab000..0x1af000 must be reserved alongside the existing log banks.

Build with this folder's CMake project and optionally set `BUDDY_EXTENSION_SOURCE` to the absolute path of Buddy5's source file. Strong `buddy_extension_init`/`buddy_extension_poll` hooks replace the weak no-op hooks; see examples/buddy5_extension.c. All buddies use nav_api.h; no direct motor GPIO/PWM writes. Buddy5 retains ownership throughout avoidance and line search, and explicitly resumes after measured stop and front line confirmation. API fields/signatures/ownership rules are V1.1. `nav_report_terrain` is telemetry only; speed assistance remains UNSUPPORTED. The default UF2 contains no ultrasonic driver.

Core0 cooperative scheduling and existing synchronized commit/stop behavior are retained. The additional diagnostic snapshots run on core0, outside motor commit IRQ masking. Any RTOS/multicore integration still needs flash lockout and timing validation. Obtain `p` and `d` before changing calibration/profile or beginning another run. Keep V1.1 at72e11ce and its original UF2 as the comparison baseline; V1.2/V1.3 physical drive regressions are not active here.
